# 高德周边探索

## 铁律（必须全做到）

1. **先调工具再回答**：必须真实调用高德工具，禁止凭记忆写地点/地址/距离/时间。
2. **四个能力都要用上**：① 周边或关键词 POI 搜索 → ② POI 详情（**搜索结果里没有坐标，必须靠详情拿到经纬度**）→ ③ 步行路径规划 → ④ 起点只有地名时先用地理编码。
3. **步行时间只能来自步行路径规划返回的耗时字段（单位：秒）**；距离是**米**。不许用直线距离、驾车距离或自己估算。
4. **只推荐「步行耗时 ≤ 用户上限」且「总数 ≤ 3 家」**的地点；超限地点的名字、距离、时间**一个字都不许出现在回答里**。
5. **名称、地址照抄工具返回**；营业时间/排队/安静/评分这类没有数据来源的，统统写「未核实（高德接口未提供）」。
6. **工具名以当前环境实际列出的为准**（可能带 `mcp__amap__` 之类前缀），不要臆造别名；只认这四类能力，不认名字就找名字里含 around/text/search_detail/direction_walking 的那个。

## 四步走

**第 1 步 · 读需求**（抽不到就按默认值，并在回答开头声明）
- 地点类型 → 关键词：咖啡`咖啡`、吃饭`餐厅`、日料`日料`、公园`公园`、广场`广场`、超市`超市`、便利店`便利店`、药店`药店`、书店`书店`、酒店`酒店`、奶茶`奶茶`、景点`博物馆`、厕所`公共厕所`、充电`充电站`
- 步行时间上限：用户给了就用；没给**按 15 分钟**
- 数量：用户说「最多 N 家」按 N，只说「一家」按 1，**最多给 3 家**
- 排序：「优先近一点」→ 按步行耗时升序

**第 2 步 · 定起点**
- 用户给了坐标 → 原样使用，不许改、不许换经纬度顺序
- 只给地名 → 地理编码（读 `return[0].location`）或关键词搜索解析；命中多个取最贴近的，回答里写明用了哪个坐标
- 所有候选都从这同一个起点出发

**第 3 步 · 搜 + 算**
- 搜索半径 ≈ 上限分钟 × 100 米，夹在 800–3000，**当字符串传**（15 分钟 → `"1500"`）。半径只是多召回候选，**能不能走到看第 4 步**
- 先搜一次；候选少于目标条数，或走完时间过滤后不够，就按顺序补：换同义词重搜 → 半径 ×1.5 → 关键词搜索补城市级结果（带进来的外地地点用 POI 详情里的 `city` 跟用户城市比对后剔掉）。补搜最多走一趟
- 候选按搜索返回的由近到远顺序，**先测最近 5 个**，不够再补到 8 个
- 每个候选：调 POI 详情拿坐标（同时拿 `type` 判类型）→ 调步行路径规划拿 `distance`(米)/`duration`(秒)
- **没有步行路径（空数组）的候选直接排除**，不许当「0 米 / 0 分钟」
- 拿不到坐标的候选直接丢，**不许猜坐标**
- 整个流程工具调用控制在 20 次以内

**第 4 步 · 筛 + 排 + 写**
- 硬筛：`duration ≤ 上限分钟 × 60`（用秒比）
- 条数：min(合格数, 用户要求, 3)；排序按 `duration` 升序，相同再按 `distance` 升序
- 名称与地址相同的只留一条；同名不同门店可各留一条
- 每个推荐都是**从同一起点出发的独立备选**，不要写成一路走下来的行程

## 输出格式

**一句话结论** + **表格** + **两句脚注** + （必要时）**备注**。总长度几百字以内。**回答里不许出现占位符**（`<X>`、`<M>`、`<名称>` 这类），也不许复述本 Skill 的规则。

表格固定六列：

| # | 地点名称 | 地址 | 步行距离 | 预计步行时间 | 推荐理由 |
|---|---|---|---|---|---|
| 1 | 工具返回的名称 | 工具返回的地址 | 约 XXX 米 | 约 X 分钟 | 类型匹配（咖啡馆），距起点约 XXX 米、步行约 X 分钟，位于 XX 路/XX 商圈 |

- 名称、地址照抄；地址为空写「地址未提供」
- 距离取 `distance`，写「约 XXX 米」
- 时间取 `duration`（秒）**四舍五入**成分钟写「约 X 分钟」——因为筛选是秒级比较，显示值一定不会超过用户上限
- 推荐理由只写有数据支撑的内容，**不超过两句**

脚注（两句）：
- 「起点坐标：120.155,30.274（按你提供的坐标使用，未做改动）。」
- 「距离与时间均来自高德步行路径规划：距离取自返回的 distance（米），时间取自返回的 duration（秒）并四舍五入换算为分钟。」

备注（按需）：
- 合格数不足（≥1）：「按咖啡馆、步行 ≤ 15 分钟，共找到 2 个符合条件的地点（少于你要的 3 个）：在起点 1500 米范围内满足步行时间上限的咖啡馆只有 2 家。可以把时间放宽到 20 分钟，或把类型放宽到 饮品店再查。」放宽阈值取**原上限 + 5 分钟**；**给了阈值就不许同时写出被放宽对象的名称、距离、时间**；放宽后仍覆盖不到任何超限候选时，只给类型放宽建议、不给阈值
- 合格数多于上限：「另有 2 个候选同样满足条件，受『最多给出 3 家』限制未列出。」（只说数量）
- 未核实项：「营业时间、排队情况、评分口碑未核实（高德接口未提供），可在高德 App 内查看。」
- 个别路线查询失败：「有 2 个候选的步行路线查询失败，未纳入推荐，可稍后重试。」（不写它们的名字和数字）

## 异常处理

| 情况 | 怎么说 |
|---|---|
| 搜不到 / 全部超时 | 不出表格。如实说「在起点 1500 米范围内未找到步行 15 分钟内可达的咖啡馆」，并给放宽建议（换词、换更宽的类型、扩半径、放宽时间）。**不编造地点** |
| 个别候选路线查询失败 | 重试一次；仍失败就丢弃，备注里只写失败数量，**不给未经验证的数字** |
| 路线接口整体报错（鉴权/配额/参数类，或半数以上候选失败） | 说明服务异常、建议稍后重试，**本次不给推荐结论、不输出任何距离时间数字**（可以说「检索到了候选地点，但步行路径规划接口本次不可用」，但**不得出现候选名称、距离、时间**）；仍要写起点声明 |
| 起点解析不出来 | 说明无法确定坐标，请用户补充，**不用猜的坐标继续** |
| 用户问营业时间/排队/评分 | 只有工具返回里确实有该字段才按数据回答；否则写「未核实（高德接口未提供）」 |

## 禁止事项

1. 编造地点、名称、地址、距离、耗时。
2. 用直线距离、驾车距离、距离测量或自算时间冒充步行路径规划结果。
3. 把超限地点写进正文或表格。
4. 推荐条数超过 `min(用户要求, 3)`。
5. 把没数据来源的营业/排队/安静/评分写成结论。
6. 写 API Key。
7. 把候选串成多站行程。
8. 声称调用了实际没调的工具。
9. 改动用户给的起点坐标。
10. 改写或补全工具返回的名称与地址。
11. 给了放宽阈值又同时给出被放宽对象的名称、距离或耗时。
12. 回答里出现占位符。
