# Qoder × OceanBase 参赛项目设计：资料混合检索助手（CourseNote Search）

> 面向学习/科研的"资料（课件、论文、笔记）混合检索 + 问答"工具
> 技术结合：seekdb（向量 + 全文 + 结构化条件混合检索）为主，PowerContext（记忆）为可选增强
> 项目资产路径：powercontext 仓库 `qoder/` 目录（分支 `2026-competition-ecosystem`）

## 1. 痛点（真实场景）

学习科研中，资料散落在多门课的课件、论文 PDF、实验记录、组会纪要里：
- 想要"某门课关于某概念的讲法"时，只能在多个 PDF 里 Ctrl+F 手工翻找
- 复习时记不清"老师当时强调过什么 / 论文里怎么定义这个方法"
- 问同学/助教要等回复

## 2. 项目能力（核心功能）

1. **资料入库**：上传 PDF / Markdown / 纯文本 → 解析 → 按语义分块 → 每块生成 embedding → 写入 seekdb
2. **混合检索**：一次查询同时用「向量近邻 + 全文匹配 + 结构化过滤（课程/来源/标签）」
   - 示例：课程过滤 = "机器学习"，全文关键词 = "过拟合"，语义查询 = "如何缓解过拟合"
3. **带出处的问答**：检索 Top-K 片段 → 交给大模型（MiniMax）生成答案 → 每条答案标注来源（文件名 + 片段位置）
4. **资料管理**：文档列表、删除、标签、按课程分组统计
5. （可选增强）**记忆增强**：用 PowerContext 记住用户的课程、薄弱知识点与检索偏好，下次检索自动带上

## 3. 技术架构

```
┌──────────────┐   上传/查询    ┌────────────────────────┐
│  Web 前端     │ ───────────▶ │  后端 (FastAPI)         │
│ (静态页)      │ ◀─────────── │  /upload /search /ask    │
└──────────────┘   JSON         │  /docs /stats            │
                                └───┬──────────────┬──────┘
                     文档分块+向量   │              │  检索 SQL
                                    ▼              ▼
                     ┌──────────────────┐   ┌────────────────────┐
                     │ MiniMax embo-01  │   │ seekdb (MySQL 协议) │
                     │ 1536 维 embedding │   │ docs / chunks 表   │
                     │ (可切本地模型)    │   │ VECTOR + FULLTEXT  │
                     └──────────────────┘   └────────────────────┘
                                                     ▲
                                            可选：PowerContext 记忆
                                     (记住课程偏好 / 薄弱点 / 检索历史)
```

## 4. 数据模型（seekdb）

```sql
CREATE TABLE docs (
  doc_id     BIGINT PRIMARY KEY AUTO_INCREMENT,
  title      VARCHAR(512)  NOT NULL,
  source     VARCHAR(255)  NOT NULL,   -- 文件名/URL
  course     VARCHAR(64)   NOT NULL DEFAULT '未分类',
  tags       VARCHAR(255)  NOT NULL DEFAULT '',
  chunk_cnt  INT           NOT NULL DEFAULT 0,
  created_at TIMESTAMP     NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE chunks (
  chunk_id   BIGINT PRIMARY KEY AUTO_INCREMENT,
  doc_id     BIGINT       NOT NULL,
  seq        INT          NOT NULL,    -- 文档内序号
  heading    VARCHAR(255) NOT NULL DEFAULT '',
  content    TEXT         NOT NULL,    -- 全文索引
  embedding  VECTOR(1536),             -- MiniMax embo-01
  course     VARCHAR(64)  NOT NULL DEFAULT '未分类',  -- 冗余以便过滤
  score_hint DECIMAL(10,4)
);
-- 全文索引 + 向量索引 + 标量过滤
```

混合检索（一次查询同时用三种能力）：

```sql
SELECT c.chunk_id, c.doc_id, c.heading, c.content,
       VECTOR_DISTANCE(c.embedding, :query_vec) AS dist,
       MATCH(c.content) AGAINST (:kw IN NATURAL LANGUAGE MODE) AS kw_score
FROM chunks c
WHERE c.course = :course           -- 结构化条件
  AND (MATCH(c.content) AGAINST (:kw IN NATURAL LANGUAGE MODE) OR 1=1)
ORDER BY dist ASC
LIMIT 10;
```

## 6. 为什么这个项目适合拿分

- **技术结合可核对**：检索结果来自 seekdb 的一条混合检索 SQL（向量 + 全文 + 过滤），可展示 SQL 与结果
- **实用价值**：解决真实的"资料找不到"痛点，团队自身可用
- **完成度可控**：范围小（1 个后端 + 1 个前端 + 1 个表结构），Qoder 几天内可产出
- **可复现**：提供 seed 数据 + 一键脚本 + 验证样例（预期输出）
