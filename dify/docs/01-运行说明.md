# 《午夜便利店·阿夜的账本》运行说明

> Dify × OceanBase 大赛作品 · 提交目录：`dify/`
> 全部配置示例均使用**占位值**，仓库内不含任何真实密钥。

---

## 1. 作品是什么

凌晨 1:47 的街角便利店，收银员**阿夜**记得你所有的小动作——你换掉的那包薄荷糖、你说过的胡话、你欠的账。

玩家与阿夜聊天、点单、搞恶作剧、也可以质疑她"记错了"；阿夜会把值得记住的事写进她的记忆库，
下一次（**新会话**）她会用这些记忆跟你算旧账。玩到后期，你会解锁"合伙人"结局。

| 玩法 | 你做什么 | 阿夜怎么回应 |
|---|---|---|
| 翻旧账 | 新会话里随便说句话 | 她主动提起你上次的恶作剧 / 口味偏好 |
| 整蛊任务 | "把薄荷糖标签换成后悔药" | 她给你派具体任务，完成后好感度变化 |
| 记忆盲盒 | "你还记得我上次干了什么吗？" | 她可能把**城市传闻**当成你的事说；你一句纠正，她当场认错并把真话写进记忆 |
| 结局 | 持续互动 | 好感度 + 整蛊数决定 黑名单 / 熟客 / 合伙人 |

## 2. 技术架构与分工

```
        ┌─────────────────────────────────────────────────────────┐
        │  Dify WebApp（作品入口，评审直接在这里玩）               │
        │  Chatflow「阿夜的账本」：14 个节点线性编排               │
        └───┬──────────────┬──────────────────────┬───────────────┘
            │ HTTP Request │ HTTP Request         │ HTTP Request
            ▼              ▼                      ▼
   ┌────────────────┐ ┌──────────────────┐ ┌──────────────────────────────┐
   │ 侧车 sidecar   │ │ PowerContext     │ │ 侧车 sidecar（状态读写）      │
   │ 8090           │ │ 8848             │ │ 8090                         │
   │ 混合检索/落库  │ │ 记忆写/召回      │ │ player_state / event_log     │
   └───────┬────────┘ └────────┬─────────┘ └──────────────┬───────────────┘
           │ MySQL 协议        │                          │
           ▼                   ▼                          ▼
   ┌────────────────────────────────────────────────────────────────┐
   │ seekdb（OceanBase AI 原生数据库，2881）                        │
   │   nightstore.lore           设定/商品/整蛊/结局/传闻（混合检索）│
   │   nightstore.player_state   玩家账本（好感度/欠账/章节）        │
   │   nightstore.event_log      事件流水（每轮一行，可核对）        │
   │   powermem.memories         PowerContext 的记忆表               │
   └────────────────────────────────────────────────────────────────┘
```

| 组件 | 职责 | 在哪能核对到 |
|---|---|---|
| **Dify** | 核心流程编排：意图判定 → 双路检索 → 角色生成 → 状态机 → 双写回 → 输出账本 | 提交 DSL（`dsl/aye-ledger-chatflow.yml`）+ 运行日志/节点 trace |
| **seekdb** | ① 设定库（人物/商品/整蛊事件/结局/传闻），向量 + 全文 + 结构化过滤**混合检索**；② 玩家账本与事件流水（应用数据存储） | `docs/03-技术结合证据.md` 里的检索 SQL、命中结果、event_log 行 |
| **PowerContext** | 跨会话记忆：玩家偏好、恶作剧、口头禅、状态快照；被后续会话语义召回并写进阿夜的台词 | `GET /api/v1/memories?user_id=…` 列表 + 召回 score + 台词里的引用 |

**为什么两个都上**：seekdb 管"客观设定与账本"（可 SQL 核对），PowerContext 管"主观记忆"（可语义召回）。
两者分工不重叠，也都真实参与每轮对话。

## 3. 运行环境与版本

| 组件 | 版本 | 说明 |
|---|---|---|
| Dify | **1.18.0** | 官方 `docker/docker-compose.yaml`，本地自部署 |
| seekdb | **1.4.0.0**（`oceanbase/seekdb:latest`） | MySQL 协议，端口 2881 |
| PowerContext | 仓库 `2026-competition-ecosystem` 分支源码 | Python 3.12，HTTP API 端口 8848 |
| 侧车 sidecar | 本仓库 `dify/backend/` | Python 3.9+ 标准库 + vendor 的 PyMySQL，端口 8090 |
| 模型 | MiniMax `MiniMax-M2.5`（对话）/ `embo-01`（向量，1536 维） | 也可换成任意 OpenAI 兼容模型 |

硬件：4 核 8G 可跑（Dify 官方全家桶约 3~4G 内存）；磁盘需 ≥ 10G（Docker 镜像约 3G）。

## 4. 部署步骤

### 4.0 准备

```bash
# Docker（国内建议配置 registry-mirrors）
docker version

# 准备密钥（占位值请替换成你自己的）
export MINIMAX_API_KEY=sk-xxxxxxxx
```

### 4.1 启动 seekdb

```bash
cd dify/deploy
docker compose -f seekdb.yml up -d seekdb
# 验证
docker exec -it nightstore-seekdb mysql -h127.0.0.1 -P2881 -uroot -e "SELECT 1;"
```

> 想和 PowerContext 共用一个实例：把 PowerContext 的 `OCEANBASE_HOST=127.0.0.1`、`OCEANBASE_PORT=2881` 指过来即可（本作即此配置）。

### 4.2 启动侧车（seekdb 访问层）

```bash
cd dify/backend
cp .env.example .env      # 填 SEEKDB_* / MINIMAX_* 等占位值
python3 -m app.main       # 监听 0.0.0.0:8090（也可在任意目录执行 python3 dify/backend/run.py）
# 验证
curl http://127.0.0.1:8090/health
```

> 也可以用 `cd dify/deploy && docker compose -f seekdb.yml up -d sidecar` 以容器方式跑。

### 4.3 灌入种子数据

```bash
cd dify/backend
python3 -m app.seed
# 输出示例：{"ok": true, "lore_rows": 35, "embed_provider": "minimax", ...}
```

这一步会：建库建表 → 写入 35 条设定（人物 5 / 商品 12 / 整蛊 8 / 结局 4 / 传闻 6）→ 用当前 embedding provider 预计算向量。

> **换 embedding provider 后必须重跑一次**（或 `curl -XPOST localhost:8090/admin/reindex`），
> 否则库内向量与查询向量不在同一空间，检索会失真。

> 如果之前的容器被清理过（`docker ps -a` 看到 seekdb 容器 Exited 或数据目录为空），
> 重新执行 4.1 ~ 4.3 即可完整恢复：设定数据在 `data/lore.json` 里，`app.seed` 会重建表并重新灌入。

### 4.4 启动 PowerContext

```bash
git clone https://github.com/<你的账号>/powercontext-2026.git
cd powercontext-2026
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[server]"            # 需要外网；若离线请提前下载 wheel

cp .env.example .env
```

> 放在侧车之后启动：PowerContext 的 embedding 走侧车的 `/v1/embeddings` 代理。

编辑 `.env`（占位值）：

```bash
# LLM：任意 OpenAI 兼容端点即可（这里用 MiniMax）
LLM_PROVIDER=openai
LLM_API_KEY=<你的 Key>
LLM_MODEL=MiniMax-M2.5
OPENAI_LLM_BASE_URL=https://api.minimax.chat/v1

# Embedding：MiniMax 的 embeddings 不是 OpenAI 兼容格式，
# 所以走本作侧车提供的 OpenAI 兼容代理 /v1/embeddings
EMBEDDING_PROVIDER=openai
EMBEDDING_API_KEY=<你的 Key>
EMBEDDING_MODEL=embo-01
EMBEDDING_DIMS=1536
EMBEDDING_OPENAI_PASS_DIMENSIONS=false
OPENAI_EMBEDDING_BASE_URL=http://127.0.0.1:8090/v1

# 存储：复用 seekdb 实例（也可以留空用内置嵌入式 seekdb）
DATABASE_PROVIDER=oceanbase
OCEANBASE_HOST=127.0.0.1
OCEANBASE_PORT=2881
OCEANBASE_USER=root
OCEANBASE_PASSWORD=
OCEANBASE_DATABASE=powermem
OCEANBASE_COLLECTION=memories
OCEANBASE_EMBEDDING_MODEL_DIMS=1536

# HTTP API
POWERMEM_SERVER_HOST=0.0.0.0
POWERMEM_SERVER_PORT=8848
POWERMEM_SERVER_AUTH_ENABLED=false
```

```bash
# 启动前先准备存储（见 §6 的"重启误判表不存在"问题）
python3 dify/scripts/init_powercontext.py

# 启动
python -m server.cli.server --host 0.0.0.0 --port 8848 --no-open-browser
# 验证
curl http://127.0.0.1:8848/api/v1/system/health

# 预置一条演示记忆（可选）
python3 dify/scripts/init_powercontext.py --memory
```

### 4.5 启动 Dify

```bash
cd dify/deploy/dify
cp .env.template .env
# 修改 SECRET_KEY / INIT_PASSWORD（本地可用默认值）
docker compose up -d
# 首次启动需要拉镜像（国内请配置 registry-mirrors，例如 docker.m.daocloud.io）
docker compose logs -f api
```

> 本目录已包含官方 compose 需要的三个配置片段（从 Dify 1.18.0 官方仓库同步）：
> `ssrf_proxy_conf/`、`nginx_conf/`、`sandbox_conf/`——官方 compose 默认从
> `docker/ssrf_proxy`、`docker/nginx`、`docker/volumes/sandbox/conf` 挂载，
> 我们把路径改成了本目录下的副本，避免评委还要去下载 Dify 源码。
> 另外 `docker-compose.override.yaml` 做了三件事：
> ① 给 api/worker/web/plugin_daemon 加 `host.docker.internal:host-gateway`（容器访问宿主机的 8090/8848）；
> ② 把 api 的 5001 端口发布到宿主机（浏览器控制台需要直连 console API）；
> ③ 用一个常驻容器顶替 `agent_backend`（本作不用 Agent 节点，省一次大镜像下载）。

访问地址：

| 用途 | 地址 |
|---|---|
| 控制台（浏览器） | <http://localhost> （nginx） |
| 控制台 API | <http://localhost:5001/console/api> |
| 应用 WebApp | <http://localhost/apps>（控制台里"访问 API / 嵌入"） |

**初始化账号**（Dify 1.18 是两步：先校验初始化密码，再建管理员）

```bash
# 方式 A：控制台网页按提示填写（.env 里的 INIT_PASSWORD）
# 方式 B：脚本
export DIFY_CONSOLE=http://127.0.0.1:5001
export DIFY_EMAIL=you@example.com
export DIFY_PASSWORD='YourPass2026'      # 必须含字母+数字，至少 8 位
export DIFY_INIT_PASSWORD=nightstore      # 与 .env 的 INIT_PASSWORD 一致
python3 dify/scripts/dify_ops.py setup
```

### 4.6 配置模型（OpenAI 兼容）

Dify 1.18 的模型供应商都是**插件**，需要先装插件再添加模型：

```bash
# 1) 安装 OpenAI-API-compatible 插件（从插件市场）
python3 dify/scripts/dify_ops.py marketplace                       # 查市场插件
python3 dify/scripts/dify_ops.py install-plugin \
  "langgenius/openai_api_compatible:0.0.73@4cf123ffaa4556f079bed6c47f3a462cc825504b859b183239e74eb19136a4b5"

# 2) 添加模型（MiniMax；也可换 DeepSeek / Qwen，只改这三项）
#    控制台路径：插件 → OpenAI-API-compatible → 添加模型
#      API Base URL : https://api.minimax.chat/v1
#      API Key      : <你的 Key>
#      模型名称     : MiniMax-M2.5
```

> 也可以完全用控制台界面完成（更省事）：
> 插件 → 安装 "OpenAI-API-compatible" → 添加模型 → 填 Base URL / Key / 模型名。

#### 离线自检模式（没有任何可用模型 Key 时）

仓库自带一个 OpenAI 兼容的 **Mock 模型服务**（仅标准库），可以在不消耗任何额度的情况下
验证「Dify ↔ 侧车 ↔ seekdb ↔ PowerContext」整条链路是否打通：

```bash
# 1) 起 mock（监听 8099）
python3 dify/scripts/mock_llm.py

# 2) 把 Dify 里的模型凭证临时指向 mock（模型名保持 MiniMax-M2.5，DSL 不用改）
export DIFY_CONSOLE=http://127.0.0.1:5001 DIFY_EMAIL=you@example.com DIFY_PASSWORD='YourPass2026'
python3 dify/scripts/dify_ops.py retarget-credential --endpoint http://host.docker.internal:8099/v1

# 3) 跑一次对话，链路通 → 会正常返回阿夜的台词 + 今日账本
python3 dify/scripts/dify_ops.py chat --app-id <app_id> --query "关东煮还有吗？"

# 4) 换回真实模型
python3 dify/scripts/dify_ops.py retarget-credential --endpoint https://api.minimax.chat/v1
```

> mock 只是自检工具（`scripts/mock_llm.py`），不是作品的一部分；它返回的台词是固定的，
> 用来验证**链路与数据流**，不用于体验作品。

### 4.7 导入 DSL

控制台 → 工作室 → 导入 DSL → 选择 `dify/dsl/aye-ledger-chatflow.yml` → 导入。

脚本方式（可重复执行）：

```bash
python3 dify/scripts/dify_ops.py import            # 导入并打印 app_id
python3 dify/scripts/dify_ops.py publish --app-id <app_id>   # 发布（Service API 需要）
```

> 若提示模型不可用：应用 → 编排 → 把「意图判定」「阿夜台词」两个 LLM 节点的模型
> 换成你已配置好的模型即可（DSL 里写的是 `langgenius/openai_api_compatible/openai_api_compatible` + `MiniMax-M2.5`）。

### 4.8 开始体验

应用 → 访问 API / WebApp → 打开「午夜便利店·阿夜的账本」。

- 开场白：*"凌晨 1:47，便利店的灯刚亮……"*
- 推荐问题（点击即玩）：
  1. `关东煮还有吗？`（看检索到的商品与价格）
  2. `我叫小李，以后每周三都来买热咖啡`（写进记忆）
  3. `把薄荷糖的标签换成『后悔药』怎么样？`（整蛊任务）
  4. **新建会话**后问 `你还记得我上次干了什么吗？`（跨会话翻旧账）
  5. `我还欠多少钱？`（账本状态）

## 6. 已知限制与故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| Dify 报 `host.docker.internal` 连不上 | 容器没有该域名 | 确认 `docker-compose.override.yaml` 生效（`docker compose config` 可见 extra_hosts） |
| HTTP Request 节点报超时 | 侧车/PowerContext 没起或端口不对 | `curl http://127.0.0.1:8090/health`、`curl http://127.0.0.1:8848/api/v1/system/health` |
| 检索结果完全不相关 | 换过 embedding provider 但没重算向量 | 重跑 `python3 -m app.seed` 或 `POST /admin/reindex` |
| 记忆写入报 422 | `content` 为空 | 检查「阿夜台词」节点是否输出了 `memory_item` |
| PowerContext 启动报 `Unknown database 'powermem'` | 库没建 | 先跑 `python3 dify/scripts/init_powercontext.py`（会建库） |
| PowerContext **重启**后 health 变 degraded、报 `1050 Table 'memories' already exists` | 本分支驱动层 `check_table_exists` 对 seekdb 不友好，重启会误判"表不存在" | 每次启动前先跑 `python3 dify/scripts/init_powercontext.py`（删表让 PowerContext 重建） |
| PowerContext 回落到 SQLite | 本机缺 `pyseekdb`，嵌入式 seekdb 探测失败 | 显式配置 `DATABASE_PROVIDER=oceanbase` + `OCEANBASE_HOST=127.0.0.1:2881` |
| Dify 插件列表报 "Failed to request plugin daemon" | `.env` 缺 `PLUGIN_DAEMON_URL` | 在 `.env` 补 `PLUGIN_DAEMON_URL=http://plugin_daemon:5002` 后 `docker compose up -d api worker` |
| Dify 容器起不来（ssrf_proxy / nginx / sandbox 反复重启） | 官方 compose 依赖 `docker/ssrf_proxy`、`docker/nginx`、`docker/volumes/sandbox/conf` 下的文件 | 本仓库已带 `ssrf_proxy_conf/`、`nginx_conf/`、`sandbox_conf/` 三个副本，compose 路径已改指向它们 |
| 控制台打不开 / 页面 404 | api 的 5001 没发布到宿主机 | `docker-compose.override.yaml` 已加 ports；`docker compose up -d api` |
| PowerContext 报 `rank_bm25 / slowapi is not installed` | 依赖没装全 | `pip install rank-bm25 slowapi` |
| 想离线跑（没有模型 Key） | 侧车支持离线哈希向量 | `EMBED_PROVIDER=local` 后重跑 `app.seed`；对话模型仍需一个可用模型（见 §4.6 的"离线自检模式"） |
| 灌数据时报 `MiniMax embeddings 返回异常` / 账户余额不足 | Key 没余额或被限流（`base_resp.status_code=1008`） | **侧车已内置降级**：自动改用本地确定性向量并打印警告，流程不中断；换可用 Key 后重跑 `app.seed` 或 `POST /admin/reindex` 即可恢复语义质量 |
| 对话报 `429 ... Token Plan` | 同样是模型侧额度问题 | 换任意 OpenAI 兼容模型（DeepSeek / Qwen / 本地 vLLM），或用 §4.6 的"离线自检模式"先验证链路 |

其他限制：

- Dify 主库固定 PostgreSQL（1.18 仅支持 Postgres），**seekdb 不做 Dify 主库**，而是承担本作应用数据存储与检索（题目允许的三种用法之一）。
- `infer=false`：记忆按原文存储（行为确定）；把 PowerContext 的 `infer` 改为 `true` 可让其用 LLM 做事实抽取（更智能，多一次模型调用）。
- 本作不使用 Dify 知识库，因此不依赖 Dify 的向量库；`VECTOR_STORE` 保持默认即可。
