# Dify × OceanBase 参赛作品设计：午夜便利店 · 阿夜的账本

> 题目：Just for Fun——用 Dify 做一个好玩的智能应用（20 分）
> 技术组合：**Dify（必选，核心编排）+ seekdb（设定库与玩家账本：向量+全文+结构化过滤混合检索）+ PowerContext（跨会话记忆）**
> 项目资产路径：powercontext 私有仓库 `dify/` 目录（分支 `2026-competition-ecosystem`）

---

## 0. 一句话结论

**凌晨 1:47 的街角便利店，收银员阿夜记得你所有的小动作——你换掉的那包薄荷糖、你说过的胡话、你欠的账。
（记忆在 PowerContext，设定与账本在 seekdb，整条流程由 Dify 编排。）**

- 玩法核心：对话即互动。阿夜会**翻旧账**（跨会话记忆）、会**派整蛊任务**（seekdb 事件库）、会因为**被质疑而当场"校准记忆"**。
- 技术可核对：seekdb 一条混合检索（`DBMS_HYBRID_SEARCH` 的 RRF 融合）实时挑设定；PowerContext 记忆写入 → 新会话召回 → 直接出现在阿夜的台词里。
- 交付物：Chatflow DSL（导入即用）+ 侧车服务源码 + 种子数据 + 运行说明 + 4 组验证样例 + 读写证据。

## 1. 玩法设计（创意 / 趣味 / 互动）

### 1.1 世界观与角色

| 项 | 设定 |
|---|---|
| 地点 | 「凌晨便利店」，凌晨 1:47 接班，5:00 交班，招牌只有两个字：夜间 |
| 角色 | **阿夜**：夜班收银员。毒舌、记仇、其实有点怕寂寞，招牌动作是拿蓝色便签本记账 |
| 玩家 | 便利店常客（有名字、有口味偏好、有欠账），也会搞恶作剧 |

### 1.2 核心循环（每轮 30 秒）

```
玩家输入（闲聊 / 点单 / 恶作剧 / 质疑 / 打听）
   ↓
① Dify 判定意图（LLM 结构化 JSON）
   ↓
② 检索设定：seekdb 混合检索（向量+全文+结构化过滤）→ 最贴合当前意图的商品/事件/结局文案
③ 召回记忆：PowerContext 语义检索 → 你的偏好、上次恶作剧、说过的梗
④ 读取账本：seekdb player_state → 好感度/欠账/整蛊数/章节
   ↓
⑤ 阿夜生成台词（LLM，输入=设定+记忆+账本+玩家输入，输出 JSON）
   ↓
⑥ 状态机（Code 节点）：好感度结算 / 欠账 / 整蛊计数 / 章节推进 / 结局判定
   ↓
⑦ 结局检索（seekdb，按 cond_min/cond_max/cond_pranks 结构化过滤，命中才播报）
⑧ 落库：seekdb 写 player_state + event_log；PowerContext 写记忆
   ↓
⑨ 输出「阿夜的账本」卡片（好感度条 + 欠账 + 整蛊数 + 章节）
```

### 1.3 三个"好玩"的钩子（也是三个技术落点）

| 钩子 | 玩家体验 | 技术落点 |
|---|---|---|
| **翻旧账** | 关掉页面重开（新会话），阿夜第一句就翻出你上次干的坏事："薄荷糖机里的芥末糖，我留了一包没扔。" | PowerContext 跨会话记忆召回 → 直接进 prompt |
| **整蛊任务** | 阿夜给你派整蛊任务（"把'薄荷糖'标签换成'后悔药'"），完成后给奖励/解锁支线 | seekdb `prank` 类设定 + 结构化过滤（好感度区间 cond_min/cond_max） |
| **记忆校准（记忆盲盒）** | 阿夜偶尔会"记错"（把城市传闻当你的事），玩家可以质疑 → 阿夜当场认错并把真相反写进记忆 | 混合来源生成（seekdb `rumor` 传闻库 + PowerContext 记忆）→ 质疑分支 → 记忆更新 |

> 钩子三把"技术"变成了"玩法"：玩家玩的是"抓 AI 瞎编"，内核是"检索结果 vs 已存记忆的一致性校验"。

### 1.4 章节与结局（由好感度 + 整蛊数决定）

| 章节 / 结局 | 条件 |
|---|---|
| 第一章·夜来客 | 默认 |
| 第二章·常客 | 好感度 ≥ 30 |
| 第三章·熟客 | 好感度 ≥ 60 且已完成整蛊 ≥ 2 |
| 第四章·合伙人 | 好感度 ≥ 85 且已完成整蛊 ≥ 4 |
| 结局·黑名单 | 好感度 ≤ -50 |
| 结局·普通客人 | -49 ~ 59（仅在章节推进时播报） |

结局文案存在 seekdb `lore` 表（`kind='ending'`，带 `cond_min/cond_max/cond_pranks`），由阿夜亲口说出来。

> 侧车同时提供一个 **OpenAI 兼容的 `/v1/embeddings`**（`backend/app/main.py`）：
> MiniMax 的 embeddings 接口不是 OpenAI 兼容格式（用 `texts` 而非 `input`），
> 侧车把它包成 OpenAI 形状，PowerContext 才能直接复用。

### 2.1 Dify Chatflow 节点清单（DSL 逐节点设计）

| # | 节点 | 类型 | 输入 | 输出 / 作用 |
|---|---|---|---|---|
| 1 | 开始 | start | `player_id`、`player_name`（表单，可留空） | 玩家标识 + 本轮输入 |
| 2 | 意图判定 | llm | 玩家输入 | JSON `{intent, target, is_prank, is_confront}` |
| 3 | 解析意图 | code | 上一步 JSON | `intent` / `lore_kinds` / `player_id` / `memory_query` |
| 4 | 设定检索 | http-request → `sidecar:8090/lore/search` | query、kinds | seekdb 混合检索命中（含 `semantic_score`/`keyword_score`） |
| 5 | 记忆召回 | http-request → `PowerContext /api/v1/memories/search` | query、user_id | 历史记忆列表（score） |
| 6 | 读取账本 | http-request → `sidecar:8090/state` | player_id | 好感度/欠账/整蛊数/章节 |
| 7 | 汇总上下文 | code | 三个 HTTP body | `lore_ctx` / `memory_ctx` / `state_ctx` 三段文本 |
| 8 | 阿夜台词 | llm | 设定+记忆+账本+输入 | JSON `{reply, affection_delta, balance_delta, memory_item, hit_event, action, prank_done}` |
| 9 | 状态机 | code | 台词 JSON + 旧状态 | 好感度/欠账/整蛊数/章节/账本条/结局触发值 |
| 10 | 结局检索 | http-request → `sidecar:8090/lore/search` | kinds=ending、cond 区间 | 命中才播报结局 |
| 11 | 提取结局 | code | 上一步 body | `ending_text` |
| 12 | 写入账本 | http-request → `sidecar:8090/state` | 新状态 + event | seekdb `player_state` + `event_log` |
| 13 | 写入记忆 | http-request → `PowerContext /api/v1/memories` | `memory_item` | 记忆入库（`infer=false`，行为确定） |
| 14 | 回答 | answer | 台词 + 账本 | 阿夜的台词 + 「今日账本」Markdown 卡片 |

DSL 由 `scripts/build_dsl.py` 生成（可一键重建），交付文件为 `dsl/aye-ledger-chatflow.yml`。

> 为什么加侧车而不是让 Dify 直连 MySQL：Dify 只有 HTTP Request 节点；侧车让 **DSL 保持干净、评委易导入**，
> 同时把 seekdb 的混合检索与状态机固化在可测试的代码里。

### 2.2 技术分工（评审要核对的那张表）

| 组件 | 在本作品中的职责 | 可核对的证据 |
|---|---|---|
| **Dify** | 核心流程编排：意图分流 → 双路检索 → 角色生成 → 状态机 → 记忆写回 → 输出 | DSL 文件 + 节点执行记录（trace） |
| **seekdb** | ① 设定库（人物/商品/整蛊/结局/传闻）的**向量+全文+结构化过滤混合检索**；② 应用数据存储（`player_state`、`event_log`）；③ 顺带承载 PowerContext 的记忆表 | 检索 SQL 与命中结果（含 vdist / kw / RRF 分）、`event_log` 增量行、`powermem.memories` 行 |
| **PowerContext** | 跨会话记忆：玩家偏好、上次恶作剧、说过的梗；被后续会话语义召回并写进阿夜的台词 | `GET /api/v1/memories?user_id=…` 列表 + 召回 score + 台词里出现的引用 |

**两者不重复**：seekdb = 客观设定与账本（结构化、可 SQL 核对）；PowerContext = 主观记忆（语义化、可被自然语言召回）。

## 3. 数据模型（seekdb 1.4.0.0 实测语法）

```sql
CREATE DATABASE IF NOT EXISTS nightstore;
USE nightstore;

-- 设定库：人物设定 / 商品 / 整蛊事件 / 结局 / 城市传闻
CREATE TABLE IF NOT EXISTS lore (
  id         BIGINT       NOT NULL,
  kind       VARCHAR(32)  NOT NULL,        -- profile|item|prank|ending|rumor
  title      VARCHAR(255) NOT NULL,
  content    TEXT         NOT NULL,
  tag        VARCHAR(64)  NOT NULL DEFAULT '',
  weight    INT           NOT NULL DEFAULT 0,
  cond_min   INT          NOT NULL DEFAULT -999,  -- 触发所需好感度下限
  cond_max   INT          NOT NULL DEFAULT 999,   -- 触发所需好感度上限
  cond_pranks INT         NOT NULL DEFAULT 0,     -- 触发所需「已完成整蛊数」下限
  embedding  VECTOR(1536),
  VECTOR  INDEX idx_lore_vec (embedding) WITH (distance=cosine, type=hnsw, lib=vsag),
  FULLTEXT INDEX ft_lore_content (content) WITH PARSER ngram   -- 中文必须 ngram
);

-- 玩家状态（一行一个玩家）
CREATE TABLE IF NOT EXISTS player_state (
  player_id   VARCHAR(64) PRIMARY KEY,
  player_name VARCHAR(64)  NOT NULL DEFAULT '',
  affection   INT          NOT NULL DEFAULT 0,    -- 好感度 -100..100
  balance     DECIMAL(10,2) NOT NULL DEFAULT 0,    -- 欠账（元）
  blacklist   TINYINT      NOT NULL DEFAULT 0,
  pranks_done INT          NOT NULL DEFAULT 0,    -- 已完成整蛊数
  chapter     VARCHAR(32)  NOT NULL DEFAULT '第一章·夜来客',
  updated_at  TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

-- 事件流水：每次互动一行，用于核对"真的写进数据库了"
CREATE TABLE IF NOT EXISTS event_log (
  id              BIGINT PRIMARY KEY AUTO_INCREMENT,
  player_id       VARCHAR(64)  NOT NULL,
  turn_id         VARCHAR(64)  NOT NULL DEFAULT '',
  intent          VARCHAR(32)  NOT NULL DEFAULT '',
  action          VARCHAR(255) NOT NULL DEFAULT '',
  affection_delta INT          NOT NULL DEFAULT 0,
  balance_delta   DECIMAL(10,2) NOT NULL DEFAULT 0,
  hit_event       VARCHAR(64)  NOT NULL DEFAULT '',
  created_at      TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

混合检索（seekdb 1.4 的 `DBMS_HYBRID_SEARCH`，ES 风格 DSL + RRF 融合）：

```sql
SET @p = '{
  "query": {"bool": {"must": [{"match": {"content": "关东煮还有吗"}}],
                     "filter": [{"term": {"kind": "item"}}]}},
  "knn":  {"field": "embedding", "k": 15, "query_vector": [/* 1536 维 */]},
  "rank": {"rrf": {"rank_constant": 60, "rank_window_size": 20}},
  "_source": ["id","kind","title","content","tag","cond_min","cond_max","cond_pranks",
              "_keyword_score","_semantic_score"],
  "size": 15
}';
SELECT DBMS_HYBRID_SEARCH.SEARCH('lore', @p);
```

要点（都是实测踩出来的）：

- 向量 + 全文 + 结构化过滤**一条查询**完成，RRF 融合两路分数；
- 全文索引必须 `WITH PARSER ngram`（中文），否则 `MATCH ... AGAINST` 命中不了；
- 向量字面量必须带方括号 `'[0.1,0.2,...]'`，长度等于列维度；
- `"must": []`（空数组）会报 `1210 Invalid argument`，没关键词时必须整段省略 `query`；
- 不同小版本对 DSL 过滤子句支持不一致 → 侧车在 Python 侧再做一次过滤兜底；
- 兜底路径：原生 SQL 加权排序 `0.7*(1-VECTOR_DISTANCE) + 0.3*MATCH(...)`（同样实测可用）。

### 3.1 记忆内容规范（写进 PowerContext 的 content 模板）

## 4. 侧车服务（配套后端，仓库内源码）

`dify/backend/`：**只用 Python 标准库 + vendor 的 PyMySQL（MIT）**，评委侧无需 pip install。

| 端点 | 方法 | 作用 |
|---|---|---|
| `/health` | GET | 健康检查（seekdb / PowerContext 连通状态） |
| `/lore/search` | POST | 混合检索：query、kinds、tags、cond 区间 → 命中列表 + `context` 渲染文本 |
| `/lore` | POST | 新增一条设定（自动 embedding） |
| `/state` | GET / POST | 读取 / 写入玩家状态（POST 同时追加一条事件流水） |
| `/event_log` | GET | 查询玩家事件流水 |
| `/admin/reindex` | POST | 换 embedding provider 后重算全表向量 |
| `/admin/seed` | POST | 幂等灌入种子数据 |
| `/v1/embeddings` | POST | **OpenAI 兼容** embedding 代理（给 PowerContext / Dify 用） |

配置（`.env.example`，只放占位值）：

```
SEEKDB_HOST=127.0.0.1
SEEKDB_PORT=2881
SEEKDB_USER=root
SEEKDB_PASSWORD=
DB_NAME=nightstore
EMBED_PROVIDER=minimax        # minimax=embo-01(1536维) | local=离线确定性哈希向量
MINIMAX_BASE_URL=https://api.minimax.chat/v1
MINIMAX_API_KEY=sk-xxxxxxxx
MINIMAX_EMBED_MODEL=embo-01
TOP_K=5
POWERCONTEXT_BASE_URL=http://127.0.0.1:8848
SIDECAR_PORT=8090
```

## 5. 部署与运行（评委视角）

### 5.1 组件与端口

| 组件 | 版本 | 端口 | 部署方式 |
|---|---|---|---|
| Dify | 1.18.0 | 3000（WebApp）/ 5001（API） | 官方 `docker-compose.yaml` + 本仓库 override（加 `host.docker.internal`） |
| seekdb | 1.4.0.0 | 2881 | Docker（`oceanbase/seekdb:latest`） |
| PowerContext | 仓库 `2026-competition-ecosystem` 源码 | 8848 | 源码 + venv（`python -m server.cli.server`） |
| sidecar | — | 8090 | 源码 + `python3 -m app.main`（或容器） |

### 5.2 初始化顺序

```bash
# 1) seekdb
docker compose -f dify/deploy/seekdb.yml up -d seekdb
# 2) 侧车
cd dify/backend && cp .env.example .env && python3 -m app.main
# 3) 种子数据（建表 + 35 条设定 + 向量）
python3 -m app.seed
# 4) PowerContext 存储准备（建库 + 清表，见 §6 风险）
python3 dify/scripts/init_powercontext.py
# 5) PowerContext
python -m server.cli.server --host 0.0.0.0 --port 8848 --no-open-browser
python3 dify/scripts/init_powercontext.py --memory   # 预置一条演示记忆
# 6) Dify
cd dify/deploy/dify && cp .env.template .env && docker compose up -d
# 7) 导入 DSL + 配置模型 → 打开 WebApp
```

### 5.3 已知限制（如实写进运行说明）

- Dify 主库固定 Postgres（1.18 仅支持 Postgres），**seekdb 不做 Dify 主库**，而是承担本作应用数据存储与检索（题目允许的三种用法之一）。
- 向量维度固定 1536；换 embedding provider 必须重跑 `app.seed` 或 `/admin/reindex`。
- 记忆写入默认 `infer=false`（存原文，行为确定）；改 `true` 可让 PowerContext 用 LLM 做事实抽取。
- 侧车支持离线哈希向量（`EMBED_PROVIDER=local`），**没有模型 Key 也能跑通检索链路**（语义质量下降，全文检索照常）。

## 6. 风险与对策（实测结论）

| 风险 | 实测结论 | 对策 |
|---|---|---|
| Docker Hub 拉不动 | `docker.1panel.live` 偶发 TLS handshake timeout | 改用 `docker.m.daocloud.io` 拉取后 `docker tag` 回官方名 |
| PyPI 不可达 | 本机 pip 完全连不上 | 侧车改**零依赖**（标准库 + vendor PyMySQL）；PowerContext 用现成 venv |
| HuggingFace 不可达 | HF API 全部超时 | `HF_ENDPOINT=https://hf-mirror.com`（实测 200）；或改用 OpenAI 兼容 embedding |
| PowerContext 连远端 seekdb | 驱动层 `check_table_exists` 对 seekdb 不友好，**重启会误判表不存在** → `1050 Table 'memories' already exists` → memory service 不可用 | 启动前跑 `scripts/init_powercontext.py`（删表让 PowerContext 重建）；已在运行说明中写死这一步 |
| PowerContext 嵌入式 seekdb | 本机缺 `pyseekdb`，探测失败会退回 SQLite | 显式配置 `DATABASE_PROVIDER=oceanbase` + `OCEANBASE_HOST` 指向我们的实例 |
| `DBMS_HYBRID_SEARCH` DSL 细节 | 空 `must` 报 1210；过滤子句支持不一致 | 空关键词时省略 `query`；侧车再做一次 Python 过滤 |
| 没有模型 Key | Dify/PowerContext 无法生成 | 侧车离线向量兜底；对话模型仍需一个可用模型（MiniMax / DeepSeek / Qwen 均可） |
| 内存只有 9G 可用 | Dify 全家桶吃紧 | compose 裁剪 + 关闭不需要的服务；实测可跑 |
