## 1. seekdb：一条查询同时做「向量 + 全文 + 结构化过滤」

### 1.1 表结构（向量索引 + ngram 全文索引同表）

```sql
CREATE TABLE IF NOT EXISTS lore (
  id         BIGINT       NOT NULL,
  kind       VARCHAR(32)  NOT NULL,
  title      VARCHAR(255) NOT NULL,
  content    TEXT         NOT NULL,
  tag        VARCHAR(64)  NOT NULL DEFAULT '',
  weight     INT          NOT NULL DEFAULT 0,
  cond_min   INT          NOT NULL DEFAULT -999,
  cond_max   INT          NOT NULL DEFAULT 999,
  cond_pranks INT         NOT NULL DEFAULT 0,
  embedding  VECTOR(1536),
  VECTOR  INDEX idx_lore_vec (embedding) WITH (distance=cosine, type=hnsw, lib=vsag),
  FULLTEXT INDEX ft_lore_content (content) WITH PARSER ngram
);
```

### 1.2 混合检索（DBMS_HYBRID_SEARCH + RRF）

```sql
SET @p = '{
  "query": {"bool": {"must": [{"match": {"content": "关东煮还有吗"}}],
                     "filter": [{"term": {"kind": "item"}}]}},
  "knn":  {"field": "embedding", "k": 15, "query_vector": [/* MiniMax embo-01 1536 维 */]},
  "rank": {"rrf": {"rank_constant": 60, "rank_window_size": 20}},
  "_source": ["id","kind","title","content","tag","_keyword_score","_semantic_score"],
  "size": 5
}';
SELECT DBMS_HYBRID_SEARCH.SEARCH('lore', @p);
```

实测输出（`_keyword_score` = 全文 BM25 分，`_semantic_score` = 向量语义分，`_score` = RRF 融合分）：

```
id=10  关东煮拼盘     _score=0.0328  _keyword_score=3.4284  _semantic_score=0.9765
id=12  三角饭团       _score=0.0161  _keyword_score=None     _semantic_score=0.8857
id=13  深夜泡面       _score=0.0159  _keyword_score=None     _semantic_score=0.8772
id=17  便利店热狗     _score=0.0156  _keyword_score=None     _semantic_score=0.8362
id=21  隔夜布丁（不卖）_score=0.0154 _keyword_score=None     _semantic_score=0.7921
```

> 关键词只命中"关东煮"这一条（BM25 分 3.43），其余靠**向量语义**召回（关东煮→饭团/泡面/热狗，都是热食），
> 这正是混合检索的意义：关键词没覆盖到，但语义对得上。

### 1.3 同一条语义的原生 SQL 形态（兜底路径，DSL 导入后仍可用）

```sql
SELECT id, title,
       VECTOR_DISTANCE(embedding, '<query_vec>') AS vdist,
       MATCH(content) AGAINST ('关东煮还有吗' IN NATURAL LANGUAGE MODE) AS kw
FROM lore WHERE kind = 'item'
ORDER BY (0.7 * (1 - VECTOR_DISTANCE(embedding, '<query_vec>'))
        + 0.3 * MATCH(content) AGAINST ('关东煮还有吗' IN NATURAL LANGUAGE MODE)) DESC
LIMIT 5;
```

实测输出：

```
id=10  关东煮拼盘       vdist=0.3068  kw=3.4284
id=12  三角饭团         vdist=0.7009  kw=0.0000
id=13  深夜泡面         vdist=0.8095  kw=0.0000
id=17  便利店热狗       vdist=0.9120  kw=0.0000
id=21  隔夜布丁（不卖）  vdist=1.1098  kw=0.0000
```

### 1.4 结构化过滤真的生效（结局按好感度 + 整蛊数过滤）

```bash

  -d '{"query":"","kinds":"ending","min_affection":90,"max_affection":90,"min_pranks":4,"top_k":2}'
```

### 4.5 跨会话复用的效果（这就是玩法样例 A）

新会话里玩家只说了「在吗」，阿夜的回复里就出现了上一轮的记忆内容
（"记得。你把薄荷糖标签换成『后悔药』，还惦记着拆糖机当废品卖。"），
说明召回结果真的进了 prompt，而不是后处理拼接。对应的节点 trace 见 §5。

### 4.6 记忆盲盒：她把"城市传闻"当成了玩家的事（新玩家第一次对话）

**玩家**：「你还记得我上次干了什么吗？」（该玩家此前没有任何记忆）
**阿夜**：「当然记得。听说你数出了冰柜第七层，还发现那里永远是空的——挺会给自己加戏的。」

> 「冰柜第七层」出自 seekdb `lore` 表的 `kind='rumor'` 条目（`传闻·冰柜第七层`），
> 与该玩家毫无关系——这就是"记忆盲盒"玩法的实现：**检索素材与已有记忆交叉生成**，
> 玩家一句"不对，我上次明明是把薄荷糖换成了芥末糖"就能让阿夜认错并把真话写回记忆。

对照事件流水（同一轮）：`hit_event = 传闻·冰柜第七层`。

## 5. Dify：编排链路与节点执行记录

（导入 DSL 后的实际运行记录，见 §5.1 / §5.2；可用
`python3 dify/scripts/dify_ops.py trace --app-id <app_id>` 复现。）

### 5.1 应用结构

- 应用名：午夜便利店·阿夜的账本
- 模式：advanced-chat（Chatflow）
- 节点数：14（LLM×2、Code×4、HTTP Request×6、Start×1、Answer×1）
- 链路：

```
开始 → 意图判定(LLM) → 解析意图(Code) → 设定检索(HTTP→seekdb)
     → 记忆召回(HTTP→PowerContext) → 读取账本(HTTP→seekdb) → 汇总上下文(Code)
     → 阿夜台词(LLM) → 状态机(Code) → 结局检索(HTTP→seekdb) → 提取结局(Code)
     → 写入账本(HTTP→seekdb) → 写入记忆(HTTP→PowerContext) → 回答
```

## 6. 复现这些证据的最短命令

```bash
# 0) 服务
cd dify/deploy && docker compose -f seekdb.yml up -d seekdb
cd ../backend && python3 -m app.main &                 # 侧车 :8090
python3 -m app.seed                                   # 灌数据
python3 ../scripts/init_powercontext.py               # 准备 PowerContext 存储
# （PowerContext 用仓库源码启动，:8848）

# 1) 一键自检（seekdb / 混合检索 / 状态 / 事件流水 / 记忆写入召回）
bash dify/scripts/smoke_test.sh

# 2) Dify 侧
export DIFY_CONSOLE=http://127.0.0.1:5001 DIFY_EMAIL=nightstore@local DIFY_PASSWORD=nightstore
python3 dify/scripts/dify_ops.py import
python3 dify/scripts/dify_ops.py chat --app-id <app_id> --query "关东煮还有吗" --player-id player_demo
python3 dify/scripts/dify_ops.py trace --app-id <app_id>
```
