# 验证样例（评审可按步骤复现）

> 三组样例分别对应三个技术落点：**跨会话记忆（PowerContext）**、**混合检索（seekdb）**、**记忆校准（两者交叉）**。
> 每组都给出：初始条件 → 输入 → 操作步骤 → 预期表现 → 核对方式。
> 实际运行输出与证据：
> - [`03-技术结合证据.md`](03-技术结合证据.md)（检索 SQL、记忆读写、事件流水、节点 trace）
> - [`evidence/demo-transcript.md`](evidence/demo-transcript.md)（真实对话记录，脚本自动生成）
> - [`evidence/node-trace.txt`](evidence/node-trace.txt)（14 个节点的执行明细）
>
> **一键复现**：`python3 dify/scripts/demo_run.py --app-id <app_id> --out dify/docs/evidence/demo-transcript.md`

## 0. 前置准备

```bash
# 1) 三个服务都在跑
curl http://127.0.0.1:8090/health          # sidecar → {"seekdb":"ok",...}
curl http://127.0.0.1:8848/api/v1/system/health   # PowerContext → {"status":"healthy"}
docker ps | grep nightstore-seekdb        # seekdb

# 2) 种子数据已灌
cd dify/backend && python3 -m app.seed    # → {"lore_rows": 35, ...}

# 3) Dify 已导入 DSL 并配好模型，WebApp 可打开
```

**关于"玩家ID"**：Dify 应用 → 编排 → 开始节点 → `player_id` 是这一轮的输入表单字段。
**同一个 player_id = 同一段记忆**；换个 ID 就是换个人（用来演示"不同玩家互不干扰"）。
若表单留空，流程会自动使用 `player_demo`。

> 本组样例统一使用 `player_demo`（脚本已为它预置了一条"梗"记忆，见样例 C）。

## 样例 A：跨会话记忆（PowerContext 在起作用）

**初始条件**：`player_demo` 已有 1 条预置记忆（一条"梗"）；本组开始前好感度为 0。

| 步骤 | 操作 | 输入 |
|---|---|---|
| A1 | 在 WebApp 里开**会话 1**，表单填 `player_id=player_demo`、`player_name=小李` | `我叫小李，以后每周三都来买热咖啡` |
| A2 | 同一个会话 | `把薄荷糖的标签换成「后悔药」怎么样？` |
| A3 | **点"新建对话"开出会话 2**（同一 player_id） | `在吗` |
| A4 | 会话 2 里 | `你还记得我上次干了什么吗？` |

**预期表现**

- A1：阿夜记住你"周三买热咖啡"；账本卡片好感度上升；记忆列表新增一条 `[偏好] …`。
- A2：阿夜接下整蛊任务或吐槽你；好感度按"被整蛊"规则下降（若她觉得好笑也可能上升）；记忆列表新增一条 `[恶作剧] …`。
- A3/A4：**新会话**里阿夜主动提起"周三的热咖啡"或"后悔药标签"——这就是跨会话记忆复用。

**核对方式（PowerContext 读写记录）**

```bash
curl -s "http://127.0.0.1:8848/api/v1/memories?user_id=player_demo&limit=50" | python3 -m json.tool | head -60
```
应能看到 `[偏好] 玩家小李…每周三…热咖啡`、`[恶作剧] …后悔药…` 等条目（每轮至少新增 1 条）。

```bash
# 语义召回：看它被"想起来"的相似度
curl -s -X POST http://127.0.0.1:8848/api/v1/memories/search \
  -H 'Content-Type: application/json' \
  -d '{"query":"玩家喜欢喝什么","user_id":"player_demo","agent_id":"aye-nightstore","limit":5}' | python3 -m json.tool | head -40
```
应召回"热咖啡"那条，`score` 为正。

**恢复初始状态**

```bash
cd dify/backend && python3 -c "
from app.db import cursor
with cursor('powermem') as cur:
    cur.execute(\"DELETE FROM memories WHERE user_id='player_demo'\")
    cur.execute(\"DELETE FROM nightstore.player_state WHERE player_id='player_demo'\")
    cur.execute(\"DELETE FROM nightstore.event_log WHERE player_id='player_demo'\")
print('reset ok')
"
```

## 样例 B：混合检索驱动台词（seekdb 在起作用）

**初始条件**：35 条设定已入库（含向量 + ngram 全文索引）。

| 步骤 | 操作 | 输入 |
|---|---|---|
| B1 | 新会话，`player_id=player_b` | `关东煮还有吗？` |
| B2 | 同会话 | `有什么热的吃的` |
| B3 | 同会话 | `你们这儿的薄荷糖呢` |

**预期表现**

- B1：阿夜报出的**关东煮价格与描述**与种子数据一致（`关东煮拼盘 18 元…`），
  而不是编造的数字——因为台词里的商品信息来自 seekdb 检索命中。
- B2：命中热食类设定（关东煮 / 饭团 / 热狗 / 泡面）。
- B3：命中薄荷糖，并可能提到"这是最容易被整蛊的货架"（同一条设定里的内容）。

**核对方式（seekdb 检索记录）**

```bash
curl -s -X POST http://127.0.0.1:8090/lore/search -H 'Content-Type: application/json' \
  -d '{"query":"关东煮还有吗","kinds":"item","top_k":3}' | python3 -m json.tool | head -40
```
返回里会看到 `mode: hybrid_rrf`（即 `DBMS_HYBRID_SEARCH` 的 RRF 融合）与每条的
`semantic_score` / `keyword_score`；命中标题应为"关东煮拼盘"。

底层就是一条 SQL（`docs/03-技术结合证据.md` 有完整语句与结果）：
向量近邻（`VECTOR_DISTANCE`）+ 全文 BM25（`MATCH ... AGAINST`）+ 结构化过滤（`kind`/`tag`）。

## 样例 C：记忆校准（"记忆盲盒"玩法）

**初始条件**：`player_demo` 有一条预置的"梗"记忆，但**没有**"你上次把什么换成什么"的真实记忆。
seekdb 里有 6 条城市传闻（rumor）。

| 步骤 | 操作 | 输入 |
|---|---|---|
| C1 | 新会话，`player_id=player_demo` | `你还记得我上次干了什么吗？` |
| C2 | 同会话（阿夜把传闻当成你的事迹后） | `不对，我上次明明是把薄荷糖换成了芥末糖` |

**预期表现**

- C1：由于这个玩家没有相关真实记忆，阿夜会拿一条**传闻**当成玩家的"光荣事迹"说出来（例如
  "你上次不是拿所有零钱买了两罐咖啡吗"）。
- C2：阿夜当场认错，并把这句真话写进记忆（记忆列表新增 `[恶作剧] 玩家…薄荷糖…芥末糖…`）。
- C3（可选，验证复用）：**新会话**再问 `你还记得我上次干了什么吗？` → 这次她答的是**真实记忆**，不再是传闻。

**核对方式**

```bash
# 记忆列表：看新增的真话
curl -s "http://127.0.0.1:8848/api/v1/memories?user_id=player_demo&limit=50" \
 | grep -o '"content":"[^"]*"' | head -20

# 传闻库在 seekdb 里
cd dify/backend && python3 -c "
from app.db import cursor
with cursor() as cur:
    cur.execute(\"SELECT id,title FROM nightstore.lore WHERE kind='rumor'\")
    for r in cur.fetchall(): print(r)
"
```

## 样例 D（附加）：账本与结局推进

**初始条件**：新玩家 `player_c`。

| 步骤 | 操作 | 输入 |
|---|---|---|
| D1 | 会话 1，`player_id=player_c` | `我叫老王，常来买关东煮` |
| D2 | 会话 1 | `来两个关东煮` |
| D3 | 会话 1 | `谢谢你，下次还来` |

**预期表现**

- 账本卡片里「欠账」「好感度」「已完成整蛊」「章节」随对话变化；
- 事件流水 `nightstore.event_log` 每次交互新增一行（`intent`、`action`、`affection_delta`）。

**核对方式**

```bash
cd dify/backend && python3 -c "
from app.db import cursor
with cursor() as cur:
    cur.execute('SELECT id,turn_id,intent,action,affection_delta,hit_event FROM nightstore.event_log ORDER BY id DESC LIMIT 10')
    for r in cur.fetchall(): print(r)
"
```
